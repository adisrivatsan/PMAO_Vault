# Vault restructure: one folder per type, one markdown file per item

## Intent

The vault is currently six flat JSON files plus a derived workbook. Nothing is
readable or searchable per item, and every ingest rewrites whole files. The goal
is a vault where each thing the PM tracks is its own markdown file in a folder
named for its type, with frontmatter fields an LLM (or grep) can filter on.

This is step 1 of 2. Step 2 (separate spec) is making `pmao ingest` easy to run
daily on material from Teams and email. The tool has no Teams/email connection;
the user drops exported/pasted text into the vault.

## Goals

- Simple, human-readable vault: open a folder, see what's there.
- Every item is a markdown file with a required `type` frontmatter field.
- A `SCHEMA.md` in the vault tells the LLM where things go and how to tell
  similar types apart, including "when unsure, don't guess, put it in `inbox/`
  and ask".
- Existing commands (`init`, `ingest`, `status`, `summarize`, `lint`, `export`,
  `config`) keep working against the new layout.

## Non-goals

- No Teams/email connectors (step 2 covers the ingest workflow only).
- No new item types beyond those below.
- No database or index file; folders plus frontmatter are the index.

## Anti-goals

- Do not silently drop data from existing JSON vaults during migration.
- Do not let the LLM file something it is unsure about; it goes to `inbox/`.

## Layout

```
vault/
  SCHEMA.md
  project-config.yaml
  projects/     type: project     (was initiatives.json)
  tasks/        type: task        (was actions.json)
  people/       type: person      (was roster.yaml)
  meetings/     type: meeting     (was meetings.json)
  decisions/    type: decision    (was decisions.json)
  notes/        type: note | hypothesis | fact   (hypotheses.json, facts.json)
  docs/         source material (was transcripts/)
  inbox/        items the tool could not place; user resolves
  workbook.xlsx derived, regenerated by `pmao export`
```

Decisions stay in their own folder (user's call). Hypotheses and facts live in
`notes/` distinguished by `type`.

## Frontmatter

`type` is always required. Fields carry over from the current models:

- project: id, name, status (`not_started|in_progress|ready|complete`),
  priority, owner, due, people, last_touched; body holds current_state,
  next_steps, last_touch_comment, notes.
- task: project (id), owner, due, status (`open|done`).
- person: name, aliases, role.
- meeting: project, purpose, attendees, date.
- decision: project, owner, rationale, date.
- note: type (`note|hypothesis|fact`), project (nullable), stated_by/owner.

Filenames are slugs of the name/title (e.g. `projects/pricing-model.md`); the
`id` field stays for stable references.

## Schema rules (SCHEMA.md content)

Seed with the judgment-call tests, to be refined by the user over time:

- Task vs project: a task is one action with one owner and a due date; a
  project has several steps or several people.
- Decision vs note: a decision records something agreed or resolved; anything
  else (context, opinion, observation) is a note.
- Hypothesis vs fact: a hypothesis is a belief to be validated; a fact is a
  sourced claim already true.
- Unsure where something belongs: write it to `inbox/`, do not guess.
- SCHEMA.md is living: each misfiling becomes one added line.

## Constraints

- Python CLI, existing deps (`pyyaml`, `openpyxl`); frontmatter parsed with
  `pyyaml`, no new dependency.
- Existing LLM backends (claude/codex) and the skills prompts in
  `pmao/skills/` are reused; prompts updated to the new types.
- Backups/atomic-write behaviour of `vault.py` preserved per file.

## Left to the builder (marked as my calls)

- Migration: provide `pmao migrate <vault>` converting the old JSON layout into
  the new folders (my call; not requested explicitly, but needed to avoid
  stranding existing vaults). Old files left in place until the user deletes them.
- How ingest proposes and applies diffs per file (keep the current
  confirm-then-apply flow).
- Whether `inbox/` items are surfaced by `status`/`lint` (my call: yes, as a
  count with filenames).
- Slug collision handling.
